# 회의·인수인계 노트 (Claude Code용)

> 새 세션은 CLAUDE.md와 이 파일을 먼저 읽는다. 사용자가 "회의모드"라고 하면 아래 '회의 진행 규칙'대로 한다.
> 최종 갱신: 2026-11-11 (패치 6.5, versionCode 65)

## 0. 회의 진행 규칙 (사용자 요청)
- "회의모드 시작" = **논의 모드**: 코드·브라우저 조작 없이 안건만 논의한다(코드를 읽어 사실 확인하는 건 OK). 결정 전에는 코드를 고치지 않는다.
- 안건은 사용자가 말한 순서대로 **처음부터 하나하나 정하면서** 간다. 한 안건에서 결론이 나면 이 파일(§3 결정사항)에 바로 저장하고 다음 안건으로 간다.
- **필요한 건 바로 이야기한다**: 정해야 할 것, 걸리는 점, 현재 수치(코드에서 확인)를 먼저 말하고, 질문은 한 번에 묶어서 제안과 함께 묻는다. 허락부터 묻지 않는다.
- 두괄식·간단 명료. 결정 내용은 회의록에 파일이 아니라 기록으로 남긴다(이 파일 + claude.ai 프로젝트 '게임제작'의 `claude/회의록-*.md`). 파일로 따로 만들어 보내지 않는다.
- 구현·배포는 사용자가 "업데이트해/배포해"라고 할 때만 커밋·푸시·패치 번호·APK/AAB 빌드(기존 규칙). 회의 중 결정은 코드에 옮기라고 할 때 옮긴다.
- 비공개 테스트 12명 모집은 사용자가 직접 진행 중 → 논의 제외.

## 3. 결정사항
### 안건 1. 퍼즐(그림 맞추기) 난이도 — 확정(구현 대기)
- 현재(변경 전) `ZONE_DIFF.jig`: 1~90 3, 91~180 4, 181~240 5, 241~300 6, 301~480 7, 481~720 8 (퍼즐은 3라운드마다 1번).
- **확정**: 상한 7×7(49조각). 조각 수 = 1~90 3×3 · 91~180 4×4 · 181~360 5×5 · 361~540 6×6 · 541~720 7×7.
- **확정**: 맞는 자리에 두면 조각 고정(선택 불가).
- **확정**: 난이도 보완은 '비슷한 조각이 많은 장면(하늘·바다 같은 단색 영역이 넓은 배경)을 후반에 더 자주'. 원본 보기는 지금처럼(힌트 1개) 유지.
- **확정**: 조각 회전 스페셜 라운드(거울 도전 라운드와 같은 틀) — 7×7 구간(541~)부터. 조작: 조각 선택 → 선택한 조각을 다시 누르면 90도 회전, 다른 조각을 누르면 자리 바꿈, 고정은 자리·방향이 모두 맞을 때. 보상: 처음 깨면 보너스 코인 50, 지도에 ⟳ 표시, 처음 만나면 설명 시트.
- **확정**: 회전 라운드 빈도 = 541~ 퍼즐 라운드 중 12라운드마다(543·555·…·711, 총 15번). 보너스 코인 50은 거울과 같음.
- **확정**: 시작 때 제자리 조각 0개로 섞기(지금은 최대 n²/4개 남음). 회전 라운드는 자리·방향 모두 틀리게 섞음.
- **확정**: 비슷한 조각이 많은 장면(후보: 별빛 하늘·하늘섬·푸른 바다, 눈 덮인 산은 그림 보고 결정) 사용 = 361~540(6×6) 확률 50%, 541~720(7×7) 확률 70%. 구현 전에 후보 배경을 실제 조각으로 잘라 확인.
- 구현 메모: `ZONE_DIFF.jig`, `initJig`/`renderJig`/`jigClick`, 거울 구조(`isMirror`: 틀린그림 r≥511이면 `(r-511)%6===0`, `CHAL_SET`, `CHAL_BONUS`=50, `P.mirrorSeen`, 지도 `.chal`).

### 안건 2. 과자 나라 라운드 확장 — 확정(구현 대기)
- **확정**: 목적은 십이지 친구 12마리를 다 쓰는 것(11×11·12×12 판 추가). 최대 **600라운드**(301~600, 300라운드 추가). 새 구간은 본 게임 지역 오픈에 연동(600라운드 기준으로 구간 편성).
- **확정**: 별 3개 기준 시간 줄이기는 **아직 적용하지 않음**(지금처럼 칸 수×3+30초 유지. 11×11=393초, 12×12=462초).
- **확정**: 구간 편성 — 301~450(150라운드) **11×11**, 본 게임 별빛 하늘(z3) 오픈 연동, 구간 이름 '별사탕 하늘' / 451~600(150라운드) **12×12**, 하늘섬(z4) 오픈 연동, 구간 이름 '구름 사탕섬'. 기존 1~300은 그대로.
- **확정**: 오늘의 과자는 지금 그대로(7~10), 11·12 포함은 따로 다룸.
- 구현 메모(코드 반영은 지시 때): `MAXC=300→600`, `PART`에 구간 2개 추가(z:3·4), `tools/candy/gen.py` 문제집 11×11·12×12 확장(`CANDY_BANK`은 약 +80KB, 생성 시간 실측 필요), 판 크기 표(`roundN`/`sizeOf`), 친구 줄 12칸 UI, 업적 `candyClear` 단계에 400·500·600 추가, 칭호 `candyStar` 점검, 지도 장식·구간 안내판, 서버 `candy_round` 최대값 점검.

### 안건 3. 수익모델/보상형 광고 — 확정(프로모션 때 구현)
- **확정**: 비공개 테스트 기간에는 광고를 넣지 않는다. **프로모션을 시작할 때** 광고를 넣는다(그때 업데이트로 AdMob SDK·Play 광고 선언·데이터 보안(광고 ID)·개인정보처리방침·콘텐츠 등급·UMP 동의·스토어 문구 '광고 없이' 수정을 한꺼번에).
- **확정**: 보상은 **하트 1개**(본 게임 하트/과자 쿠키). 하루 한도를 둔다. 전면 광고 없음.
- **확정**: 하루 한도 **5번**(본 게임·과자 합산, 기기 시간 자정 초기화), 하트가 0일 때만 광고 버튼 표시.
- **확정**: 사이드로드 APK에도 광고를 넣는다(Play판과 같은 AdMob, 플레이버 구분만 유지).
- **확정**: 광고 콘텐츠는 **전체이용가용** — AdMob 앱 설정에서 최대 광고 콘텐츠 등급을 G(일반 시청자)로 제한하고 도박·성인 등 민감 카테고리 차단. (필터라 100% 보장은 아님, 수익은 조금 줄 수 있음)
- **확정**: 웹(GitHub Pages)판은 지금 광고 없음(웹 광고는 자체 도메인·별도 광고 계정이 필요해 나중에). 아이 대상 연령 선언은 나중에 사용자가 Play Console에서 확인 후 광고 설정 반영.

### 안건 4. 기존 밸런스 — 확정(구현 대기)
- 확인한 현재값: 하트 10·10분/1(시간당 6개), 실수 5번이면 실패(하트 1 잃음), 힌트 10·30분/1(시작 5, 상점 200코인), 클리어 코인 별 1/2/3개 = 25/50/100(차액만), 하트·쿠키 100코인, 지역 별 70%(필요 별 189/270 ×4지역, 하늘섬 315/450, 천국 441/630).

- **확정**: 하트·힌트·쿠키 하트 최대 **5개**(지금 10). 충전 간격은 그대로(하트 10분/1, 힌트 30분/1), 쿠키도 10분/1. 기존 보유분은 5개로 맞춤(보상 없음, 비공개 테스트라 사용자 적음).
- **확정**: 로직 터치 문제는 **일단 폭 최적화**(단서 영역을 줄여 칸을 키움, 칸 최소값 12×12 17px·그 외 22px 재점검). 확대 미리보기(A)+오입력 완충(B)은 폭 최적화 결과를 보고 판단(보류). 돋보기는 되살리지 않음. 현황: 돋보기는 6.0에서 버튼만 없앴고(코드 `zoomLogicTo`·`lgZoom` 남아 있으나 안 불림, 두 손가락은 판 이동만, 패치 노트 6.0 문구는 '확대·이동'이라 어긋남). 칸 크기(390px폭 공식 추정): 5×5 60·6×6 51·7×7 42·8×8 36·10×10 27·12×12 23px, 권장 터치 44~48px. 단서 폭 `rcw=maxR*(12이상 13, 그 외 15)+12`, 단서 높이 `chh=maxC*16+8`.
